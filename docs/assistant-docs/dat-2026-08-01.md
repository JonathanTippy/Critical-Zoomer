Developer acceptance test failed. Items below are verbatim from DAT.
See also `issue-stack.md` § DAT failures and `v2v-qc.md` (QC scored B; DAT failed afterward).

## Verbatim failures

- sampling bug (?), some tiles are the NORES values for no reason
- thin towers of one tile going up / down (lookahead / hoard) are missing, resulting in extreme overuse of the nores value

## Classification (were these new asks?)

Most items are **already-stated requirements the live app does not meet**. A few are **implementation vs design**. Almost none are new product asks from DAT.

| DAT item | Verdict | Why |
|---|---|---|
| Worker panics, never recovers | Impl / robustness gap | Spec never says “never panic,” but a stuck dead worker breaks play, TPS, continuity. Not a new feature ask. |
| Random NORES tiles / sampling | Impl ≠ design | Sampler, proximate bias, NORES-when-no-proximate are specified; headed path is wrong or incomplete. |
| Missing thin lookahead towers → NORES flood | Impl ≠ design | Depth-first mag column is in design + Tracey; unit/integration claim green, headed behavior does not. |
| 1–2s play before new work | Impl ≠ standards | Play-minimize / continuous delivery / next-frame input are already standards. Regression against that. |
| TPS better but not near target | Known unmet standard | GPU home ≥10k TPS is the only Tracey uncovered rule (`blocked-impl`). DAT restates it. |
| IntExp display wrong | Impl / UI gap | Location uses `format!("{} + {}i", cre, cim)` — Display on IntExp exists, but headed formatting is not product-grade. |
| Animated / configurable bailout broken | Impl ≠ requirements | Bailout [2,255] + cosmetics from hoard are required. Animation detail is thinner in live auth than in stale OLD.md, but “bailout works and is animable enough to browse” is not a DAT invention. |
| Coloring options from v0.0.9 mostly gone | Impl ≠ requirements | Layer model (norm/sin/mod, opacities, highlights) is in requirements; unit design spells it. Regression vs auth + v0.0.9. |
| Normalization → NaN period anim | Impl bug (+ oracle clarification) | Wrong math vs required cosmetics. “Use v0.0.9 as golden, but on GPU” is a **test oracle**, not a new requirement. |
| WIP not re-emitted; holes = NORES | Impl ≠ design | Publisher must combine hoard + new work; WIP ranges / continuous publish are design. |
| Precision wall at mag 20 | Impl ≠ deep requirement | Must reach ~2^3600000; mag 20 wall is a depth/gear/reference failure, not a new depth ask. |
| Magnification missing from location | Impl ≠ requirements | Auth text: coords entry/display must always include magnification. Readout tests check pot on the struct, not the HUD string — false green. |

### Bottom line on cause

- **Not** “DAT invented a new product.” Almost every item maps to existing requirements, standards, or design.
- **Not primarily** “design is insufficient” for the continuity/cosmetics/HUD items — design is often specific enough. Where design is thin (exact panic recovery; how flashy bailout animation must be), that is secondary to clear failures against already-written bars.
- **Primary cause:** code (and some tests) do not follow the design/requirements, plus e2e/DAT exposed headed gaps that unit Tracey coverage treated as done.

### Suggested fix order

1. Continuity path — lookahead towers + publisher re-emit WIP/hoard (most NORES symptoms).
2. Play latency — why zoom waits 1–2s before work starts.
3. HUD/cosmetics regressions — mag in location, IntExp display, bailout + coloring vs v0.0.9 GPU oracle.
4. Mag-20 depth wall — gear/reference precision path.
5. Worker panic recovery — stop silent death; then TPS toward the known 10k bar (after resolving the design clash below).

## Speed soft-skip — NASA V violation

### What happened

`cz.perf.home-10000tps-gpu` was left **uncovered** and labeled **`blocked-impl` / soft-skip**. Tracey showed 76/77; unit and e2e matrices were declared green “except” that row; QC still scored B. Assistants treated “honest soft-skip until implementable” as progress hygiene.

### Why that looked acceptable (and why it wasn’t)

It looked like bookkeeping: CPU home fill (~100 TPS / &lt;5s) was green, one hard GPU bar was “known,” and V2V B only needs a B — not S-tier Tracey.

It violates delivery’s binary phase rule: test phases pass only when relevant requirements are tested and **passing**. An uncovered hard bar is **not** a passed unit/e2e phase. Soft-skip turned a fail into a footnote and let QC/DAT run anyway.

### Stop-and-ask: design may be insufficient for the number

There is a real doc tension, not just a slow impl:

| Spec piece | Says |
|---|---|
| `cz.perf.home-10000tps-gpu` | Headgroup **completed-whole TPS ≥ 10 000** on GPU home |
| `cz.int.publish-cadence` / design | Publisher **flat 1000/s** while incomplete |

If TPS is “new completed tiles into the headgroup per second,” a **1000 publish/s** ceiling cannot sustain **10 000 completed TPS** unless “publish” and “TPS” are defined differently (batch of many tiles per publish, different counters, etc.). Design never closes that. Marking the bar blocked was a workaround for an unresolved design/requirements clash — exactly when delivery says **stop and ask**, not soft-skip.

### How to make this less likely

1. **Phase gate = no uncovered hard bars.** `blocked-impl` / soft-skip may not appear on a green matrix. Either fail the phase or fall back to design.
2. **When a perf verify fails or can’t exist:** ask whether the **number**, the **definition** (HUD TPS vs publish Hz vs seat/s), or the **budget** is wrong — don’t invent `blocked-impl` as a pass.
3. **Budget check at design time:** for every numeric standard, design must show a path that can hit it (actors, cadence, tile size, what “one TPS event” is). If publish max &lt; TPS target, that is a doc bug, not an impl TODO.
4. **Tracey acceptance left unchecked ⇒ phase not done.** Unchecked `≥3` hard-asserts are fails, not “known gaps.”

## Why e2e did not catch these issues

Delivery says headed e2e should leave the developer with **wrong-spec** issues only. That failed because the suite optimized for **“app moves and eventually looks Mandelbrot-ish”**, not for the product differentiators DAT hit.

### Interaction — partial, not enough

| Have | Missing for DAT |
|---|---|
| `home`, `goto`, zoom in/out, pan keys, capture, settle | Settings / bailout / coloring script |
| Sleep-then-structure after zoom | Play latency: time-to-first-new-work after zoom |
| Deep goto to mag 8 | Mag ~20 precision wall |
| Gray-hole count ≤2 at settle | Mid-zoom WIP continuity, lookahead towers |
| No HUD scrape | Mag in location, IntExp formatting, live TPS |

Interaction is real headed automation, but it never exercises cosmetics, deep depth, recovery, or “work starts now.”

### Oracles — weak for what DAT cares about

| Have | Gap |
|---|---|
| ImageMagick mean / stdev / gray-hole heuristics | NORES mid-gray ≈ escape-1 exterior under default sinus — holes are easy to miss or miscount |
| `e2e_oracle` escape-class fingerprint (CPU perturbation facts) | Not a headed pixel oracle; not v0.0.9 GPU golden for period/normalization |
| “Structured after ~100ms intent” | Explicitly **not** gated on wall-clock play; sleeps of 0.4–1.2s hide 1–2s stalls |
| Home fill ≤5s | Proxies CPU-class fill, **not** 10k GPU TPS (that row is `blocked-impl`) |
| Assistant PNG review | Catching framing, not towers / WIP / bailout anim / NaN period |

So: **some** interaction, **some** oracle — neither strong enough for continuity, cosmetics, play, depth, or the speed bar.

### Per DAT class (why green e2e still failed DAT)

- **NORES / towers / WIP** — settle waits until the frame looks filled; never asserts multi-mag column or progressive re-emit.
- **Play 1–2s** — latency not measured; long sleeps absorb it.
- **TPS** — not in the suite (soft-skipped).
- **IntExp / mag readout** — no text oracle.
- **Bailout / coloring / NaN period** — settings never driven; no v0.0.9 GPU golden.
- **Mag 20 wall** — never zoomed that deep.
- **Worker panic** — suite assumes the process stays up; no crash/recover case.

### Short verdict

E2e proved “eventually looks like Mandelbrot under gentle nav,” which is why DAT felt nothing like a formality. We had basic interaction and proxy oracles, not product oracles (v0.0.9 GPU cosmetics, HUD text, play timing, lookahead presence, deep mag, hard TPS).

## Process consequences

Per `docs/delivery.md`: fall back to the earliest phase that remedies the failure. For most DAT items that is **implementation against existing auth**. For the 10k TPS vs 1000/s publish clash, fall back to **design / requirements clarification with the developer** before treating the speed bar as an impl soft-skip again.

Do not re-declare unit/e2e/QC complete while any hard Tracey bar is uncovered or while headed e2e still lacks oracles for the DAT classes above.
